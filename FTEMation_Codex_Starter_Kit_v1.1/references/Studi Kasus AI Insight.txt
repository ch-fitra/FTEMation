Studi Kasus AI Insight untuk Workload Assessment Analysis
Latar Belakang
PT ABC punya aplikasi Workload Assessment Analysis berbasis Laravel. Karyawan mencatat aktivitas kerjanya, sistem
menghitung beban kerja dalam satuan full time equivalent, lalu AI menilai potensi otomasi setiap aktivitas: high,
medium, atau low, lengkap dengan alasan dan rekomendasinya.
Masalah
Dari User perlu mengetahui seperti apa penilaian AI terhadap aktifitas dan memberikan rekomendasi berapa beban
kerja yang bisa dikurangi, dan apa yang sebaiknya diotomasi lebih dulu.
Tugas
Buat aplikasi web Laravel 13 yang terhubung ke layanan AI, dengan fitur:
    1. Login: akun demo dicantumkan di README.
    2. Import Excel: impor data Workload Assessment dari dataset yang kamu buat sendiri.
    3. Analisis AI: level otomasi tiap aktivitas, beserta alasan dan rekomendasinya.
    4. Kesimpulan AI: ringkasan, estimasi pengurangan full time equivalent, dan prioritas otomasi per karyawan
         dan departemen.
    5. Dashboard: total full time equivalent, potensi otomasi, perbandingan departemen, dan detail aktivitas.
    6. Grouping: kelompokkan aktivitas serupa lintas karyawan/departemen beserta total full time equivalent-nya.
    7. Export: laporan PDF/Excel dan results.json.
Nilai plus: aplikasi mobile (Flutter) yang memakai API Laravel untuk menampilkan dashboard dan hasil analisis AI.
Ketentuan Dataset (minimum)
     Minimal 50 aktivitas, 10 karyawan, 3 departemen; sebagian aktivitas dibuat mirip agar grouping bisa diuji.
     Kolom wajib: activity_id, employee_id, employee_name, department, activity_name, description, frequency
         (daily/weekly/monthly), volume (jumlah per periode), duration_minutes.
     Rumus full time equivalent dijelaskan di README (mis. menit aktivitas/tahun ÷ menit kerja efektif/tahun).
Ketentuan Teknis
     Model AI dan arsitektur bebas. Output AI harus terstruktur, tervalidasi, dan konsisten untuk aktivitas serupa.
     Sistem harus menangani kegagalan API, mendukung retry, dan memakai cache agar data yang tidak berubah
         tidak dianalisis ulang.
     Prompt AI disimpan dalam file terpisah. README menjelaskan pendekatan, kriteria High/Medium/Low,
         asumsi pengurangan full time equivalent, dan model AI yang dipakai.
Contoh Format results.json
File results.json wajib berisi hasil analisis seluruh aktivitas dari dataset yang kamu buat, dengan struktur berikut:
{                                                       Aturan untuk results.json:
    "activities": [                                          Setiap aktivitas memiliki activity_id unik sesuai
      {
        "activity_id": "ACT-0001",                              dataset.
        "automation_level": "high",                          Nilai full time equivalent dan estimasi
        "reason": "Input data manual berulang",                 pengurangannya dihitung oleh program.
        "recommendation": "OCR dan integrasi ERP",           File ini dihasilkan melalui aplikasi, tidak dibuat
        "group_id": "manual_data_entry",
        "fte": 0.1458,
                                                                manual.
        "estimated_fte_saving": 0.1021,
        "status": "success"
      }
    ]
}


Yang Dikumpulkan
       1.   Source code (ZIP) beserta README cara menjalankan dan kredensial demo.
       2.   Dataset Excel yang kamu buat dan pakai untuk import.
       3.   ERD database dalam format gambar atau PDF.
       4.   Video demo 8–10 menit dengan penjelasan suara.
       5.   results.json berisi hasil analisis seluruh aktivitas sesuai format di atas.
